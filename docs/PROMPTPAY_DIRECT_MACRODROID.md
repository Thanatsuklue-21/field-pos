# PromptPay บัญชีร้าน (ไม่มีค่าธรรมเนียม) + MacroDroid

สถานะ: **OWNER-APPROVED 2026-11-16** — เปลี่ยนจาก Beam (มีค่าธรรมเนียม) เป็น PromptPay เข้าบัญชีร้านโดยตรง
ธนาคาร: กรุงศรี · PromptPay ผูกเบอร์มือถือ · ปิดบิลอัตโนมัติเมื่อแจ้งเตือนตรงกับบิลที่รอจ่าย

## หลักความปลอดภัย (ห้ามเปลี่ยนโดยไม่มี owner approval)

- QR ล็อกยอดตามบิลจริง (EMVCo dynamic QR, CRC-16/CCITT-FALSE) — **ไม่บวกเศษสตางค์** (NON-VAT, ราคาเมนู = ราคาขาย)
- QR รอจ่ายได้ **1 ใบต่อยอดเงิน** — ใบที่สองยอดเดียวกันถูกปฏิเสธจนกว่าใบแรกจะจ่าย/ยกเลิก/หมดเวลา (15 นาที)
- แจ้งเตือนปิดบิลได้เมื่อ: รหัสลับ header ถูก + เป็น "เงินเข้า" + ยอดตรงทุกสตางค์ + มาหลังสร้าง QR และก่อนหมดเวลา + มี QR รอจ่ายยอดนั้น **ใบเดียว**
- แจ้งเตือน 1 ข้อความใช้ได้ 1 บิล — ข้อความเดิมซ้ำภายใน 10 นาทีถือเป็นซ้ำ
- **ไม่เก็บข้อความแจ้งเตือนดิบ** (มีชื่อผู้โอน · PDPA) เก็บแค่ยอด ทิศทาง เวลา และ HMAC hash
- ยอดคงเหลือ ("คงเหลือ", "balance") และรายการโอนออกไม่ถูกใช้เป็นยอดรับเงิน
- แจ้งเตือนไม่มา → ปุ่ม "เห็นเงินเข้าในแอปธนาคารแล้ว" (ยืนยัน 2 ขั้น) บันทึก `field_audit` ว่าใครกด
- การขายยังผ่าน checkout/split-payment เดิมที่ server อ่านสถานะ charge ซ้ำก่อน commit และใช้ charge ได้ครั้งเดียว

## ตั้งค่า Vercel (field-pos → Settings → Environment Variables → Production)

| ตัวแปร | ค่า |
|---|---|
| `PROMPTPAY_PROVIDER` | `direct` |
| `PROMPTPAY_DIRECT_ID` | เบอร์ PromptPay ของร้าน 10 หลัก เช่น `08xxxxxxxx` |
| `BANK_NOTIFY_SECRET` | ข้อความสุ่มยาว ≥ 32 ตัว (สร้างด้วยตัวจัดการรหัสผ่าน) — ห้ามส่งในแชท |
| `BANK_NOTIFY_BANK` | `krungsri` (ใช้เป็นป้ายในบันทึก) |

แล้ว Redeploy · ตรวจที่ `/settings` ว่าไม่มีคำเตือน `bank_notify_not_configured`

## ตั้งค่า MacroDroid บนมือถือ Android ที่ลงแอปกรุงศรี

1. ติดตั้ง MacroDroid → อนุญาต **Notification Access**
2. Macro ใหม่
   - **Trigger:** Notification → Notification Received → เลือกเฉพาะแอป **Krungsri (KMA)**
   - **Action:** Web Interactions → HTTP Request
     - Method: `POST`
     - URL: `https://field-pos.vercel.app/api/payments/bank-notification`
     - Header: `x-field-bank-key` = ค่าเดียวกับ `BANK_NOTIFY_SECRET`
     - Content type: **`text/plain`**
     - Body: เลือกตัวแปร "ข้อความแจ้งเตือน" (และหัวข้อ) จากปุ่มตัวแปรของ MacroDroid
       (ใช้ text/plain เพื่อไม่ให้เครื่องหมาย `"` ในข้อความทำให้ JSON พัง)
3. ปิดการประหยัดแบตเตอรี่ของ **MacroDroid และแอปกรุงศรี** · เปิดแจ้งเตือนเงินเข้าในแอปกรุงศรี
4. มือถือเครื่องนี้ต้องล็อกหน้าจอด้วยรหัส และไม่ติดตั้งแอปที่ไม่จำเป็น (มันเห็นแจ้งเตือนธนาคาร)

## ทดสอบก่อนเปิดใช้ (ต้องทำ)

1. **ส่งข้อความแจ้งเตือนจริงของกรุงศรีให้ทีมพัฒนา 2–3 แบบ** (เงินเข้า / โอนออก / มีคงเหลือ) — ปิดชื่อคนและเลขบัญชีได้ แต่ต้องคงคำและรูปแบบตัวเลขไว้ เพื่อยืนยันตัวอ่านข้อความ (`parseBankNotification`) กับรูปแบบจริง
2. สร้าง QR ยอดเล็ก (เช่น ฿1.00) → โอนจากบัญชีอื่น → บิลต้องปิดเองภายในไม่กี่วินาที + มีเสียง "ได้รับเงิน…"
3. โอนยอดผิด → บิลต้องไม่ปิด
4. ปิด MacroDroid → โอน → ใช้ปุ่ม "เห็นเงินเข้าแล้ว" → บิลปิด และมีบันทึก audit
5. ยกเลิก QR (เปลี่ยนเป็นเงินสด) → โอนเข้ามาทีหลัง → ต้องเป็น "unmatched" ไม่สร้างบิล

## ข้อจำกัดที่ยอมรับ

- ถ้ามีคนอื่นโอนยอดเดียวกันพอดีในช่วงที่ QR ยอดนั้นรอจ่าย ระบบอาจปิดบิลผิด (โอกาสต่ำ) — ตรวจรายการ unmatched ทุกวันตอนปิดยอด (`GET /api/payments/bank-notifications`)
- การยืนยันมาจากแจ้งเตือนของแอปธนาคาร ไม่ใช่จากธนาคารโดยตรงแบบ Beam
- ตาราง `field_promptpay_direct` / `field_bank_notifications` ยังไม่อยู่ใน Full Backup (การกันใช้ charge ซ้ำอยู่ใน `field_pos_requests` ซึ่ง backup แล้ว) — งานถัดไป

## เน็ตหลุด / PromptPay แบบ Offline (owner-approved 2026-11-16)

- POS จำเบอร์รับเงิน PromptPay ของร้านไว้ในเครื่องหลังเปิดแอปครั้งแรกที่มีเน็ต แล้วสร้าง QR ล็อกยอดได้เองโดยไม่ต้องต่อ server
- เน็ตหลุด: เลือก PromptPay → "สร้าง QR ในเครื่อง (เน็ตหลุด)" → ลูกค้าสแกน → ดูสลิปหรือแอปธนาคาร → "เห็นเงินเข้าแล้ว · บันทึกบิล"
- บิลเก็บในเครื่อง สถานะ **ยังไม่ตรวจยอด** เน็ตกลับแล้วส่งขึ้น server เอง และ server จับคู่กับแจ้งเตือนธนาคารขาเข้าที่ยังไม่ถูกใช้ ยอดเท่ากัน ช่วง 5 นาทีก่อนถึง 30 นาทีหลังกดบันทึก
  - เจอ 1 รายการ → ตรวจยอดแล้ว
  - ไม่เจอ / เจอหลายรายการ → ค้างตรวจ ดูได้ที่ `GET /api/payments/bank-notifications` (`offlinePromptPayUnverified`) และให้ตรวจกับแอปธนาคารตอนปิดวัน
- ถ้ามี QR ออนไลน์ค้างอยู่ จะสร้าง QR ออฟไลน์ไม่ได้ เพื่อกันรับเงินซ้ำ
- MacroDroid ควรใช้เน็ตมือถือ เพื่อให้แจ้งเตือนเข้าระบบได้แม้ WiFi ร้านหลุด
- ถ้า WiFi ยังเชื่อมต่ออยู่แต่ไม่มีอินเทอร์เน็ต ให้ปิด WiFi บนเครื่อง POS ระบบจะเข้าโหมด Offline ทันที
